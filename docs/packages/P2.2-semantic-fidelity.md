# P2.2 — semantic import and fidelity probes

Package: P2.2 semantic rules, editor states and faithful property resolution
Objective: preserve explicit semantic classifications separately from lexical
styles, expose import losses, and test actual scope/group treatments
Dependencies: v1 contracts (`c7de02c`)
Allowed paths: core import/semantic/scope, IR additions, revision/scene consumers,
Neovim semantic emission, focused evaluation fixtures and integration wiring
Contract version: IR/intent/protocol 1 with discoverable additive feature flags
Acceptance: offline tests, real Neovim group checks, pinned source/license metadata,
negative fixture, enforced metadata/byte hashes, and honest incomplete-rendering reports

## Implemented

- Standard semantic selectors `(*|type)(.modifier)*(:language)?`, explicit type
  retention (class/interface no longer collapse), and source-order priority.
- Independent per-property semantic resolution: exact type +100, modifier +100
  each, language +10, later source order wins ties. Source model checked against
  VS Code 1.95.0 code below. No model controls final colors.
- Hex shorthand/alpha; fontStyle resets; bool omission versus false; underline
  and strikethrough coexist. Unknown/malformed input is rejected, including
  shadowed/unmapped colors and duplicate JSON object keys.
- Includes keep ordered semantic layers, including repeated selectors with
  different property settings. Parent/child semantic enablement follows the
  pinned VS Code include OR behavior.
- Added selection/search/diff/gutter/terminal/completion/status mappings.
  Terminal scenes use terminal backgrounds, not assumed editor backgrounds.
- `Target.include_semantic` optionally applies property edits and lock/unlock to
  existing semantic overrides. Reports identify the semantic rule index.
- Scene semantic context composes the resolved foreground/alpha. Unknown
  enablement qualifies validation rather than passing.
- Neovim emits native LSP type and single-modifier groups after generic links.
  Combined modifier predicates, alpha flattening and priority gaps are losses.
- Explicit scope-stack probe API for the dotted/ancestor subset; scope collapse
  and unsupported selectors are named, not silently claimed faithful.
- Complete Dark+/included base pinned at upstream commit, original bytes and
  MIT license retained. Specific probes use independently specified colors.

## Compatibility

New optional IR fields: `Style.strikethrough`, `SemanticStyle.token_type` and
`priority`; empty modifier sets allow unmodified type or language rules.
Existing v1 consumers remain accepted by this engine. Older engines reject new
fields rather than discard them; clients must check `capabilities.ir_features`.
Legacy `UnderlineStyle::Strikethrough` still loads; use the bool property for new
rules. `include_semantic` defaults false to avoid silently widening old targets.
Machine import/emit returns `partial` when losses/skipped/unconsumed roles exist.
Strict duplicate-key rejection is a deliberate invalid-input compatibility change.

## Remaining limitations

Not full TextMate parsing/tokenization: exclusions, unions/priority predicates,
grammars and editor defaults remain outside the supported probe grammar. Multiple
lexical scopes are still collapsed into a reported representative role. Custom
semantic type hierarchy and default token-scope probing need extension context.
Neovim group resolution tests do not verify actual LSP token priorities in code.
No live VS Code conformance run, held-out multi-reference fidelity gate, human
preference study, or broader interpretation-quality result is claimed.
